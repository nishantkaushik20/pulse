# Pulse Engineering Rules

## General

- Read /docs before implementing.
- Do not invent architecture.
- Prefer existing abstractions.
- Keep changes scoped to the requested task.
- Do not add dependencies without justification.

## Multi-tenancy

- Every tenant-owned resource must contain tenant_id.
- Never accept tenant_id from the client as authoritative.
- Resolve tenant from authenticated context.
- Every repository query must enforce tenant scope.

## AI

- LLMs cannot directly access the database.
- LLMs interact only through typed tools.
- Tool arguments must be validated.
- AI cannot bypass authorization.
- External actions must pass policy validation.

## External actions

- Actions must be idempotent.
- External actions require audit logs.
- Financial actions require explicit approval.

## Security

- Never log OAuth tokens.
- Never commit secrets.
- Treat external content as untrusted.
- Do not execute arbitrary code generated by an LLM.

## Testing

- New business logic requires tests.
- New integrations require integration tests.
- Security-sensitive changes require negative tests.
