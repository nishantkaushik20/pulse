# Security

Security requirements for Pulse are recorded in this document.

Constraints:

- Never log OAuth tokens, authorization codes, Clerk session tokens, authorization headers, Google response bodies, or raw authentication payloads.
- Never log Gmail message bodies.
- Never commit secrets.
- Treat external content as untrusted. Gmail message content is untrusted mailbox data. It is not rendered as HTML and it is not a system instruction.
- Do not execute arbitrary code generated by an LLM.
- Security-sensitive changes require negative tests.
- Tenant id comes from membership, not from the client. A known id from another tenant is not access.

## Gmail OAuth

`POST /integrations/gmail/connect` requires an authenticated `OWNER`. Pulse stores a random `state` and PKCE verifier in Redis for 10 minutes. Google redirects to `GET /integrations/gmail/callback`, which does not require Clerk. The callback deletes the state with `GETDEL` before exchanging the code. Tenant binding is the `tenant_id` saved at connect time. The callback does not accept `tenant_id` from the query string, the body, or Google.

The authorization URL requests only `https://www.googleapis.com/auth/gmail.readonly`. That scope is restricted. A public production deployment that stores Gmail data on Pulse servers has to go through Google's OAuth verification and the applicable security assessment. Pulse does not request broader Gmail scopes and does not bypass that process.

Refresh tokens and access tokens are encrypted with AES-256-GCM under `INTEGRATION_ENCRYPTION_KEY` before they are written to PostgreSQL. The key is 32 bytes, base64-encoded. Production refuses to start when it is missing. Local Gmail routes return 503 when it is missing. The key, tokens, authorization codes, and the Google client secret are not logged.

`invalid_grant` marks the connection `REVOKED`, clears the ciphertext, and returns a stable error. It is not retried. HTTP 429 and 5xx return 503 and do not advance `last_synced_at`. Disconnect revokes the refresh token on a best-effort basis, clears ciphertext, and keeps ingested messages.

A mailbox address is globally unique. When another tenant already connected it, the callback redirects with `reason=conflict` and does not reveal that tenant.
